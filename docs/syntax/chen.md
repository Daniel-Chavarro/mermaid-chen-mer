# Chen ER Diagram (`chen-beta`)

> **Beta Feature**: This diagram type is in beta and requires the `chen-beta` diagram header.

The Chen Entity-Relationship (`chen-beta`) diagram brings Peter Chen's classic 1976 Entity-Relationship notation into Mermaid. Unlike Crow's Foot ER diagrams (`erDiagram`), Chen notation models entities as rectangles, relationships as diamonds, and attributes as ovals with explicit notation for identifiers, composite hierarchies, multivalued attributes, ISA specialization triangles with disjointness constraints, double-line total participation, and aggregations.

## Syntax & Notation Guide

### 1. Entities & Weak Entities

- **Regular entity**: Single-line rectangle.
  - `entity <id>["<label>"]` or `entity <id>`
  - Shorthand: `<id>["<label>"]`
  - Inline attribute block:
    ```mermaid
    chen-beta
      entity Persona["Persona"] {
        key codPersona
        attr nombre
      }
    ```
- **Weak entity**: Double-line rectangle.
  - `weak entity <id>["<label>"]` or `weak <id>["<label>"]`
  - Shorthand: `<id>[["<label>"]]`
  - Weak entities must use `partialKey` (dashed underline) instead of `key` and must participate totally (`==`) in at least one identifying relationship.

### 2. Relationships & Identifying Relationships

- **Regular relationship**: 2:1 aspect ratio diamond.
  - `rel <id>["<label>"]` or `relationship <id>["<label>"]` or `<id>{"<label>"}`
- **Identifying relationship**: Concentric double-line diamond.
  - `idrel <id>["<label>"]` or `identifying rel <id>["<label>"]` or `<id>{{"<label>"}}`
  - Must connect at least one weak entity with total participation and one owner with cardinality one.

#### Connectors & Cardinality

- **Chain syntax**: `<EntityA> <connA> <Relationship> <connB> <EntityB>`
  - Example: `Profesor -(1)- Imparte -(N)- Asignatura`
  - Example: `Libro <-(1)- Tiene ==(N)== Ejemplar`
- **Leg syntax**: `<Relationship> <conn> <Entity> [: "<role>"]`
- **Participation**:
  - `-` / `--` / `---` = Partial participation (single line)
  - `=` / `==` / `===` = Total participation (double line)
- **Cardinality**:
  - Arrow pointing to entity (`<--`, `-->`, `<-(1)-`, `-(1)->`, `<==(1)==`, `==(1)==>`) = Cardinality **one** (`'one'`)
  - No arrow (`---`, `===`, `-(N)-`, `==(N)==`, `-(M)-`) = Cardinality **many** (`'many'`)

### 3. Attributes

Attributes attach to entities, relationships, or parent attributes (composite):

| Attribute Type | Syntax | Visual Representation | Constraint |
|:---|:---|:---|:---|
| **Simple** | `attr name` | Single oval | Attaches to entity, rel, or composite attr |
| **Primary Key** | `key name` | Oval with solid underlined text | Strong entities only |
| **Partial Key** | `partialKey name` | Oval with dashed underlined text | Weak entities only |
| **Multivalued** | `multi name` | Concentric double oval | Any entity or relationship |
| **Derived** | `derived name` | Dashed oval | Any entity or relationship |
| **Composite** | `attr name { attr child1 ... }` | Parent oval connected to child ovals | Children attach only to parent oval |

### 4. Specialization / Generalization (ISA)

- **Block syntax**:
  ```mermaid
  chen-beta
    isa isa_persona from Persona === disjoint {
      Estudiante
      Profesor
      Autor
    }
  ```
- **Single-line syntax**:
  `Persona === isa_persona[isa: disjoint] --- Estudiante, Profesor, Autor`
- **Visuals**:
  - An inverted triangle with a centered circle.
  - Double line (`===`) from supertype indicates **total/mandatory** specialization; single line (`---`) indicates **partial/optional**.
  - `disjoint` draws an arc across the line between the supertype and the triangle. `overlapping` omits the arc.
  - The specialization graph must be an acyclic directed graph (DAG).

### 5. Aggregations & Nested Aggregations

An aggregation encapsulates an ongoing relationship between two entities as a higher-level composite object that can participate in other relationships:

```mermaid
chen-beta
  aggregation Agregado_Imparte {
    Profesor -(1)- Imparte -(N)- Asignatura
  }
  Estudiante -(N)- Cursa -(M)- Agregado_Imparte
```

- Renders as a dashed rounded rectangle container (`ClusterNode`).
- **Exact 2 + 1 invariant**: Each aggregation must contain **exactly 2 entities/aggregations** and **exactly 1 relationship** between them.
- Aggregations may be nested to arbitrary depth.

## Complete University & Library Example

```mermaid
chen-beta
  direction TB

  %% BLOQUE 1: PERSONA / ESTUDIANTE / PROFESOR / AUTOR (ISA)
  entity Persona {
    key codPersona
    attr nombre
  }

  isa isa_persona from Persona === disjoint {
    Estudiante
    Profesor
    Autor
  }

  entity Estudiante {
    attr edad
    attr direccion_electronica
    attr direccion {
      attr calle
      attr carrera
    }
    multi telefonos
  }

  entity Profesor {
    attr profesion
    attr nivel_escolaridad
  }

  entity Autor {
    key codigo_autor
    attr nacionalidad
  }

  %% BLOQUE 2: ASIGNATURA + AGREGACION (Imparte) + CURSA
  entity Asignatura {
    key codigo
    attr creditos
    attr nombre
    attr intensidad_horaria
  }

  rel Imparte {
    attr horario
    attr salon
    attr numero_grupo
  }

  aggregation Agregado_Imparte {
    Profesor -(1)- Imparte -(N)- Asignatura
  }

  rel Cursa {
    attr nota1
    attr nota2
    attr nota3
    derived nota_definitiva
  }

  Estudiante -(N)- Cursa -(M)- Agregado_Imparte

  %% BLOQUE 3: BIBLIOGRAFIA / AUTORES / EJEMPLARES / PRESTAMOS
  entity Libro {
    key codigo_libro
    attr titulo
    attr idioma
  }

  rel Bibliografia
  Asignatura -(M)- Bibliografia -(N)- Libro

  rel Escribe
  Libro -(M)- Escribe -(N)- Autor

  weak entity Ejemplar {
    partialKey numero_ejemplar
  }

  idrel Tiene
  Libro <-(1)- Tiene ==(N)== Ejemplar

  rel Presta {
    attr fecha_prestamo
    attr fecha_limite
    attr fecha_entrega
    derived dias_mora
  }

  Estudiante -(1)- Presta -(N)- Ejemplar
```
